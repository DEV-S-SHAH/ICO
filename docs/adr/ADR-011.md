# ADR-011: Tenant Isolation Model for L7 Project Memory, L8 Session Memory, L9 LLM Response Cache

**Status**: ACCEPTED  
**Date**: 2026-10-06  
**Decision Makers**: Security Engineer, Architect, Memory Engineer, Cache Engineer  
**Reviewers**: All Phase 3 Review Agents  

---

## Context

The Phase 3 architecture (PHASE3_ARCHITECTURE.md, Sections 2, 4, 5) defines three new memory/response layers with critical tenant isolation gaps identified in SECURITY_REVIEW_PHASE3.md (Sections 1, 2, 3, 18):

| Layer | Current Key Design | **Critical Gap** |
|-------|-------------------|------------------|
| **L7 Project Memory** | `project_id = hash(repo_url + default_branch)` | **No `tenant_id`** — same public repo = shared memory across tenants |
| **L8 Session Memory** | `session_id + turn_id + scope` | **No `tenant_id`, no `user_id`** — session collision = cross-tenant/user leakage |
| **L9 LLM Response Cache** | `hash(full_prompt + model + provider + params + prompt_version)` | **No `tenant_id`, no `user_id`** — cross-tenant/user response reuse |

### Risk Scenarios (SECURITY_REVIEW_PHASE3.md:85-92, 61-68)

| Layer | Attack Vector | Severity |
|-------|---------------|----------|
| **L7** | Tenant A and B both use `github.com/org/repo` → same `project_id` → Tenant B reads Tenant A's proprietary code summaries | 🔴 CRITICAL |
| **L7** | Private repo ingested by Tenant A → Tenant B with same URL accesses summaries | 🔴 CRITICAL |
| **L8** | Session IDs not globally unique → Tenant B's session ID collides with Tenant A's → conversation history leakage | 🔴 CRITICAL |
| **L8** | User A's facts/preferences served to User B within same tenant | 🔴 HIGH |
| **L9** | Tenant A's deterministic (temp=0) response cached → served to Tenant B with same prompt | 🔴 CRITICAL |
| **L9** | User A's personalized response cached → served to User B | 🔴 HIGH |

---

## Decision

**All cache keys in L7, L8, L9 MUST include `tenant_id` as a mandatory prefix/component.**

Additionally:
- **L8** MUST include `user_id` for multi-user tenant isolation
- **L9** MUST include `user_id` when caching personalized responses
- **L7** `project_id` MUST be tenant-scoped: `project_id = hash(tenant_id + repo_url + default_branch)`

---

## Tenant Isolation Model

### Identity Hierarchy

```
Tenant (API Key) 
    └── User (authenticated identity within tenant)
            └── Session (conversation context)
                    └── Project (repository knowledge scope)
```

### Key Specifications (Updated)

#### L7: Project Memory

```python
# BEFORE (VULNERABLE)
project_id = hash(repo_url + default_branch)

# AFTER (SECURE)
project_id = hash(tenant_id + repo_url + default_branch)

# Full L7 cache key for symbol/file lookup:
l7_key = f"{tenant_id}:l7:{project_id}:{file_hash}:{symbol_path}"
# or for project-level query:
l7_query_key = f"{tenant_id}:l7:query:{project_id}:{query_hash}:{commit_sha}"
```

**Authorization Check**: Before any L7 query, verify tenant has access to this `project_id` (via API key scope or explicit project grant).

#### L8: Session Memory

```python
# BEFORE (VULNERABLE)
l8_key = f"l8:{session_id}:{turn_id}:{scope}"

# AFTER (SECURE)
l8_key = f"{tenant_id}:l8:{user_id}:{session_id}:{turn_id}:{scope}"
```

**Consent Model**: 
- `user_id` derived from authenticated identity (JWT sub, API key metadata, or explicit header)
- Session creation requires explicit user consent for memory persistence
- `consent_version` in key to handle consent revocation (invalidates old entries)

#### L9: LLM Response Cache

```python
# BEFORE (VULNERABLE)
l9_key = hash(full_rendered_prompt + model + provider + params + prompt_version)

# AFTER (SECURE) - Two modes:
# Mode A: Non-personalized (classification, extraction, temp=0)
l9_key = f"{tenant_id}:l9:{hash(full_prompt + model + provider + params_hash + prompt_version)}"

# Mode B: Personalized (includes user context from L8)
l9_key = f"{tenant_id}:l9:{user_id}:{hash(full_prompt + model + provider + params_hash + prompt_version)}"
```

**Deterministic-Only Guard**: L9 only caches responses where `model_params.temperature == 0` AND `model_params.top_p == 1` (or provider equivalent). Non-deterministic responses NEVER cached.

## Per-Layer Critical Fields (Expanded from SECURITY_REVIEW_PHASE3.md Section 14)

Based on the security review's per-layer critical fields analysis, here are the **mandatory hard gate fields** for each layer. These fields **always block** on mismatch regardless of gate mode (STRICT/BALANCED).

| Layer | Critical Fields (Hard Gates) | Fuzzy-Eligible Fields (BALANCED only) |
|-------|------------------------------|----------------------------------------|
| **L0a** (Deterministic) | `function_version`, `input_hash`, `env_hash` | — |
| **L0b** (Embedding Cache) | `model_fingerprint` (model+provider+params), `text_hash` | — |
| **L1** (Exact Prompt) | `tenant_id`, `model_fingerprint`, `prompt_version`, `entity`, `quarter`, `topic` | `custom_metadata` (if declared fuzzy) |
| **L2** (Semantic) | `tenant_id`, `model_fingerprint`, `embedding_version`, `entity`, `quarter`, `topic`, `collection_version` | `topic` (if declared fuzzy), `custom_metadata` |
| **L3** (Context-Aware) | `tenant_id`, `model_fingerprint`, `embedding_version`, `entity`, `quarter`, `topic`, `collection_version`, `context_hash` | `topic`, `custom_metadata` |
| **L4** (Retrieval Cache) | `tenant_id`, `collection_version`, `filter_hash`, `top_k`, `embedding_version` | `reranker_version` (if declared fuzzy) |
| **L5** (Context Window) | `tenant_id`, `chunk_content_hashes`, `template_version`, `token_budget`, `model_fingerprint` | — |
| **L6** (Tool Cache) | `tenant_id`, `tool_name`, `tool_version`, `arg_hash`, `idempotency_key` | — |
| **L7** (Project Memory) | `tenant_id`, `project_id`, `commit_sha`, `file_hashes`, `dependency_graph_version`, `embedding_version` | — |
| **L8** (Session Memory) | `tenant_id`, `user_id`, `session_id`, `consent_version` | `scope` (if declared fuzzy) |
| **L9** (LLM Response) | `tenant_id`, `user_id` (if personalized), `model_fingerprint`, `params_hash`, `prompt_version` | — |

### Notes on Critical Fields

1. **`model_fingerprint`** = `hash(model + provider + params)` — replaces separate `model`, `provider`, `params` fields for compactness
2. **`embedding_version`** = `embedder.model_version` property (ADR-001/ADR-003 requirement)
3. **`collection_version`** = Auto-incremented on every corpus ingestion/delete
4. **`authz_version`** = Authorization policy version — **MUST be added to ALL layers** (SECURITY_REVIEW_PHASE3.md:14.2). Implementation tracked separately.
5. **`consent_version`** = Incremented when user revokes/grants session memory consent
6. **`dependency_graph_version`** = Hash of project dependency graph — changes on any dependency modification

## Vector Namespace / Collection Isolation

| Layer | Storage | Isolation Mechanism |
|-------|---------|---------------------|
| **L7 Vectors** | LanceDB | Collection per tenant: `{tenant_id}_l7_project_memory` |
| **L7 Metadata** | SQLite/PostgreSQL | `tenant_id` column + composite indexes; RLS policies in PostgreSQL |
| **L8** | Redis | Key prefix: `{tenant_id}:l8:{user_id}:...` |
| **L9** | Redis | Key prefix: `{tenant_id}:l9:{user_id}:...` (or without `user_id` for non-personalized) |

**Default Mode**: Collection isolation for all vector layers (L2, L3, L4, L7). Payload mode **DEPRECATED** for multi-tenant deployments.

---

## Cross-Layer Isolation Guarantees

| Guarantee | Enforcement |
|-----------|-------------|
| **Tenant A never reads Tenant B's L7 data** | `tenant_id` prefix in all L7 keys + collection isolation + authz check on project access |
| **Tenant A never reads Tenant B's L8 data** | `tenant_id` + `user_id` prefix in all L8 keys + Redis key isolation |
| **Tenant A never reads Tenant B's L9 data** | `tenant_id` (+ `user_id`) prefix in all L9 keys + deterministic-only guard |
| **User A never reads User B's L8/L9 data** | `user_id` in L8/L9 keys; session bound to authenticated user |
| **Semantic matches never cross tenant boundary** | Collection isolation (default) + `tenant_id` in metadata filter (payload mode) + hard gate on `tenant_id` |
